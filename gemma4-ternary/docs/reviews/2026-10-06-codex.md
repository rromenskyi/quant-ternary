## Prioritized review

1. **Fix the loss and its name before interpreting another KL curve.** [kd_loss](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/train_ternary.py:100) sums over the teacher’s top 32 probabilities but omits the remaining vocabulary mass. The same truncated quantity is reported as “KL” in [evaluate](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/train_ternary.py:106). A near-zero master self-check confirms the stored logits match; it does **not** validate full-vocabulary KL. Log top-32 mass, add a residual tail bucket to the loss, and measure true full-vocabulary KL on a smaller fixed eval set. The STE itself has an identity backward as intended ([ternary_lib.py](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/ternary_lib.py:51)); the scale rule is a design choice worth testing, since absmean with a 0.5×scale threshold is not generally the minimum-error ternary projection.

2. **Make evaluation reflect generation.** [prepare_data.py](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/prepare_data.py:132) concatenates documents into rows, so a reply can start after unrelated text. [evaluate](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/train_ternary.py:119) scores prompt, user, assistant, and document-boundary positions together. That obscures the failure users see: wrong facts, code, Russian replies, and thought loops. Add response-only, separately reported thinking/non-thinking KL; full-vocabulary KL on complete un-packed conversations; and fixed free-generation tests for factual accuracy, executable code, Russian, tool-call validity, thought closure, repetition, and long multi-turn consistency. Deduplicate prompts across train and test, including near duplicates, and keep a separate untouched test set for final selection.

3. **The export claim needs a narrower scope.** The reported MLX agreement on four rows supports the *ternary* export ([FINDINGS.md](/Users/roman220/gh/quant-ternary/gemma4-ternary/docs/FINDINGS.md:94)). But [export_mlx.py](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/export_mlx.py:47) packs every checkpoint weight as ternary, and [splice_mlx.py](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/splice_mlx.py:62) marks every replacement 2-bit. The 4-bit-attention probe therefore cannot yet be exported as trained. Save each layer’s grid and group size in checkpoint metadata, export accordingly, and compare PyTorch and MLX logits across several complete conversations.

4. **Temper two conclusions.** The warmup result changes learning rate and projection schedule together; [FINDINGS.md](/Users/roman220/gh/quant-ternary/gemma4-ternary/docs/FINDINGS.md:83) acknowledges this, so “warmup broke the plateau” remains a hypothesis. The PPL gap of roughly 3% is also weak evidence of usable quality: it includes user turns, while the generation examples remain poor ([FINDINGS.md](/Users/roman220/gh/quant-ternary/gemma4-ternary/docs/FINDINGS.md:227)). The projected token count needed to reach 4-bit KL is too uncertain to budget against ([FINDINGS.md](/Users/roman220/gh/quant-ternary/gemma4-ternary/docs/FINDINGS.md:124)).

5. **For the $200 run, spend early tokens on decisions.** Start from the best completed checkpoint. Use a short, equal-token pilot to compare group 64, 4-bit attention, and a small sensitivity-selected set of 4-bit layers against the control, reporting *quality versus exported bytes*. The current [probes](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/probes.sh:22) are useful screening, but their second pass over the same data cannot establish generalization. Then train on fresh, balanced teacher replies: code with execution checks, Russian and other target languages, genuine multi-turn and tool-use transcripts, plus broad general prompts. Audit stop-token handling because [gen_docs](/Users/roman220/gh/quant-ternary/gemma4-ternary/poc/prepare_data.py:37) now retains only documents ending in `<turn|>`. Reserve a late, small student-generated continuation set for on-policy distillation, especially from contexts that trigger loops. Track response-only generation metrics throughout; stop or redirect the run if those stall despite falling KL.

6. **Literature to apply selectively.** [LLM-QAT](https://aclanthology.org/2024.findings-acl.26/) supports your teacher-generated-data direction. [GKD](https://arxiv.org/abs/2306.13649) motivates student-generated contexts to address inference distribution shift. [BitDistiller](https://arxiv.org/abs/2402.10631) suggests testing confidence-aware distillation, while [ParetoQ](https://arxiv.org/abs/2502.02631) argues for comparing quantizer choices at equal compute and final size. [BitNet b1.58](https://arxiv.org/abs/2402.17764) demonstrates ternary training from scratch; its quality claims should not be transferred directly to post-hoc conversion of this QAT master.
