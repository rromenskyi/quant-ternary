# Review: gemma4-ternary (read-only)

## 1. Correctness risks, prioritized

**a) Loss and packing teach the wrong contexts — biggest quality leak.** `train_ternary.py:100-103` and `:106-127` score *every* token, including human/user turns and packed web text. Capacity is spent predicting prompts, and eval KL mixes user-turn surprise with assistant quality. Worse, `prepare_data.py:136-153` concatenates unrelated docs with no separator/BOS (gen docs in `gen_teacher_data.py:117` have no BOS; `tok(..., add_special_tokens=False)`), so every row contains spurious doc→doc transitions that the teacher then labels (`teacher_topk.py:56`). The FINDINGS claim that truncation/format issues are "waste, not wrong lessons" understates this: cross-doc positions are actively wrong contexts. Fix for B200: per-token loss mask (assistant/reply tokens only, or strongly downweighted prompts), plus document separators and ideally attention masking or single-doc rows for chat.

**b) Truncated, unnormalized KL.** `kd_loss` sums `p_topk·(log p_t − log p_s)` where `p_t` is full-vocab softmax (`teacher_topk.py:56-58`), so mass < 1 and the tail is dropped. Direction is fine (pushing top-k up pushes tail down via softmax), but uncertain tokens (user turns, web, code) are systematically underweighted and absolute KL understates true KL. Refs share the bias so ranking is roughly valid, but gaps vs q4_0/4-bit aren't true KL gaps. Renormalize top-k (or record tail mass), and consider larger k on high-entropy positions.

**c) Probes are confounded.** `probes.sh:23-28` forks all probes from the ternary-g128 checkpoint for a *second* epoch on the same 21M tokens (own comment, `:3-5`). Control gain (0.709→0.696) mixes fresh-optimizer/LR-restart effects with data repetition. `attn4`/`g64` change the quantizer instantly on latents adapted to g128-ternary, so their worse start (0.746) is partly shock, not steady-state cost. Read only slopes after ~1M tokens, or add a short re-adaptation before comparing.

**d) STE/scale/optimizer details (smaller).** Absmean ternary (`ternary_lib.py:28-32`) with identity STE (`:51-61`) and λ-mixing (`:111-118`, gradient stays 1 — correct) is standard. But: no gradient clipping or NaN guard in the accum loop (`train_ternary.py:322-329`); bf16 grads + STE spikes make this fragile. `SRAdamW` (`ternary_lib.py:161-199`) looks right (uniform [0,2¹⁶) SR, fp32 moments math), and the unbiasedness check is good — but on a B200 just use fp32 masters/moments and drop this risk. No learnable scale/threshold; fixed 0.5·mean threshold is the known weak point of absmean on outlier layers.

**e) Export "exact" is approximate.** `export_mlx.py:29-37` picks codes from fp32 `s` but stores `s` rounded to bf16, while training uses fp32 `s` (then bf16 weight rounding, `ternary_lib.py:32`). Relative error ~10⁻³ per group — tiny, but verify on all 64 eval rows with max-abs-diff, not 4 rows. Bit order/grouping over `in_features` matches MLX; good.

## 2. Is the eval sound?

Directionally yes (same windows, shared teacher, exact master-vs-self check), but too thin to trust conclusions: 64 rows (~131k tokens, 253 replies), no confidence intervals, PPL admitted ±1–5% wobble; user turns scored; generation judged on 4 greedy anecdotes. Missing: assistant-only KL; held-out code/multilingual/multi-turn/agentic sets (the stated B200 targets); any downstream task (MMLU/GSM8K/HumanEval/MT-Bench or cheap equivalents); size-matched baselines (E2B/E4B) on the same KL harness; scripted loop/multi-turn/fact metrics FINDINGS itself calls for. The power-law token forecast (3 noisy points) should not size the $200 run.

## 3. Are FINDINGS claims justified?

Justified: warmup run beats from-scratch ternary at equal tokens; chat data >> raw web for eval; self-generated replies + correct prefix fixed generation; PPL-within-3% vs 4-bit; loops/weak reasoning at KL 0.71.
Over-claimed or confounded: (i) "warmup broke the plateau" — lr changed 3e-5→1e-4 simultaneously (acknowledged once, then treated as warmup's win); (ii) "export is exact" — see 1e; (iii) "truncation is waste, not wrong lessons" — packing makes cut points wrong-context lessons; the `--keep-unfinished` filter (`prepare_data.py:37-48`) is still the right call; (iv) probe reads (control vs lr vs attn4) as clean ablations — see 1c.

## 4. B200 run: quality per dollar

1. Data: assistant-only loss; doc boundaries fixed; code-heavy + Russian + multi-turn + tool-use prompts; keep raised caps (2048/4096) and drop unfinished; dedupe near-identical smoltalk turns.
2. Start from master with λ-warmup, not the pilot latent (narrow-English bias), unless a probe shows warm-start wins on the *new* mix.
3. Loss/schedule: renormalized top-k KL (k=32–64, larger on high-entropy tokens); short on-policy (GKD-style) phase at the end to attack loops; cosine over the full 0.5–1B tokens, peak lr ~5e-5–1e-4 with warmup, grad-clip 1.0, fp32 optimizer.
4. Precision: let attn4/g64 probes run to slope comparison; default to keeping attention (and 1–2 most sensitive proj types) at 4-bit if the gap persists — size cost is small vs the KL prize. Decide group 64 vs 128 by measured KL-per-GB, not a priori.
5. Eval from day one: frozen multi-domain KL harness + a small generation suite (loop rate, multi-turn consistency, facts, code smoke tests).

## 5. Literature to apply (confident cites only)

- BitNet b1.58 (Ma et al., arXiv 2402.09766): absmean ternary + STE recipe you're following; supports high-lr-from-scratch but you're fine-tuning, so moderate lr + warmup is right.
- LLM-QAT (Liu et al., arXiv 2309.10944): self-generated distillation data — already applied correctly.
- GKD (Agarwal et al., arXiv 2306.13649): on-policy distillation with forward/reverse/JSD divergences — the principled fix for exposure-bias loops; matches your planned end-phase.
- MiniLLM (Gu et al., arXiv 2306.08543): reverse-KL KD improves generation quality over forward KL — consider a reverse-KL/JSD mix for the final phase.
- LSQ (Esser et al., arXiv 1902.08153): learned step-size — the missing piece vs your fixed absmean scale; even per-tensor/per-group learned multipliers usually beat fixed thresholds.
